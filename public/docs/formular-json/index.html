Formular-JSON

Eine Datei pro Formular beschreibt Felder, Validierung, Beschriftungen und Mail-Templates. Der Server prüft Einsendungen dagegen, das Embed-Skript rendert daraus das Formular.

Aufbau

SchlüsselPflichtBedeutung
idjaFormular-ID, entspricht dem Dateinamen (kontakt → kontakt.json)
versionjaGanzzahl, bei jeder Änderung erhöhen – steht im Dashboard
recipientjaEmpfänger-Alias aus der Seiten-Config. Echte Adressen stehen nie in der Formular-JSON.
fieldsjaListe der Felder, in Anzeigereihenfolge
redirectneinDanke-Seite pro Sprache, z. B. {"de": "/danke", "en": "/en/thank-you"}
submitLabelneinBeschriftung des Absende-Buttons pro Sprache
successMessageneinErfolgsmeldung am Ort, wenn es keinen Redirect gibt
mailneinsubject und body der Mail an den Empfänger, mit Platzhaltern
autoresponderneinDanke-Mail an den Absender: enabled, subject, body – nur fester Text

Feldtypen

typeBedeutungOptionen
textEinzeiliger TextmaxLength (Standard 500), minLength, placeholder, autocomplete
emailE-Mail-Adresse, wird streng geprüftreplyTo: true für das Absenderfeld (höchstens eines)
telTelefonnummer (Ziffern, Leerzeichen, + ( ) / . -)maxLength (max. 40)
textareaMehrzeiliger TextmaxLength (Standard 5000), rows
numberZahlmin, max, step
dateDatum im Format JJJJ-MM-TT–
selectAuswahllisteoptions (Pflicht)
radioEine Option aus mehrerenoptions (Pflicht)
checkboxMit options: Mehrfachauswahl. Ohne: einzelnes Ja/Neinoptions (optional)
consentZustimmung, z. B. Datenschutz – muss angehakt sein, wenn required–
hiddenVerstecktes Feld. Gilt als Benutzereingabe und steuert nichtsdefault

Jedes Feld hat name (Buchstaben, Ziffern, Unterstrich; nicht locale oder altcha), type, label pro Sprache sowie optional required, help, placeholder, default und autocomplete. Optionen haben die Form {"value": "zimmer", "label": {"de": "Zimmeranfrage", "en": "Room request"}}. Datei-Uploads (file) kommen in einem späteren Schritt.

Regeln

  • Jedes Textfeld hat ein maxLength – Standard 500, bei textarea 5000.
  • Unbekannte Felder in einer Einsendung werden verworfen.
  • Platzhalter {{feld}} dürfen nur auf existierende Felder zeigen, dazu {{_site}}, {{_form}} und {{_date}}. Die CI prüft das vor jedem Deploy.
  • Bei Auswahlfeldern setzt der Platzhalter das Label der Option ein, bei Ja/Nein-Feldern „Ja“ oder „Nein“.
  • Der Autoresponder enthält nur feste Texte, keine Platzhalter. Sonst könnte jemand Werbung in das Namensfeld schreiben und sie über unsere Domain an fremde Adressen schicken lassen.
  • Die Mail an den Empfänger nutzt das Template in der Sprache der Einsendung, sonst de. Der Autoresponder nutzt immer die Sprache der Einsendung.
  • Ohne mail-Template erzeugt der Server eine Standard-Mail mit allen Feldern als Liste.
  • Labels, Optionen und Reihenfolge bestimmen auch die Darstellung im Embed-Skript.

Öffentliche Ansicht

GET /v1/{site}/{form}/spec liefert die Datei ohne recipient, mail und autoresponder aus – das Embed-Skript braucht nur Felder und Beschriftungen.
