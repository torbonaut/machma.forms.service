Redirects & Fehler

Was nach dem Absenden passiert – im Erfolgs- und im Fehlerfall.

Redirect-Ziel

  1. Standard: redirect aus der Formular-JSON in der Sprache der Einsendung.
  2. Pro Einbindung überschreiben: data-redirect-url="/danke-zimmer" – das Skript schickt das Ziel als Feld _redirect mit.
  3. Der Server akzeptiert ein überschriebenes Ziel nur, wenn es ein relativer Pfad ist (/danke, nicht //…) oder exakt auf eine der Domains der Seite zeigt. Sonst nimmt er still den Standard. So entsteht kein offenes Redirect für Phishing-Links.
  4. Das Ziel kommt in der Antwort zurück, das Skript leitet dorthin weiter. Ohne Ziel zeigt es die Erfolgsmeldung am Ort.
{ "ok": true, "redirect": "/danke" }

Fehler

Fehler zeigt das Embed-Skript immer direkt am Formular an, mit den Texten aus der Antwort in der Sprache der Seite.

{ "ok": false, "error": "validation",
  "message": "Bitte die markierten Felder prüfen.",
  "fields": { "email": "Bitte eine gültige E-Mail-Adresse angeben." } }

Statuscodes

StatuserrorBedeutung
200–Angenommen. Auch Spam (Honeypot, zu schnell) bekommt still 200, wird aber nicht versendet.
400challenge_invalidSpamschutz fehlt, ist abgelaufen oder wurde schon benutzt – Seite neu laden.
403forbiddenDie Website (Origin) ist für diese Seite nicht freigegeben.
404not_foundSeite oder Formular gibt es nicht.
413too_largeMehr als 32 KB.
415unsupportedKein application/json.
422validationFelder ungültig, Details pro Feld in fields.
429rate_limitedZu viele Einsendungen von dieser IP, Wartezeit im Header Retry-After.
502send_failedDie Mail konnte nicht zugestellt werden (SMTP).

Ohne JavaScript

Ohne JavaScript läuft kein Spamschutz, deshalb wird nie versendet. Einen klassischen Form-POST mit Server-Redirect gibt es bewusst nicht – zeige stattdessen per <noscript> Telefon oder Mailadresse.
