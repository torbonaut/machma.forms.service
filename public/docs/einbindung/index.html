Einbindung

Jede Website bindet Formulare über ein Skript ein – egal ob Astro, reines HTML oder WordPress.

Modus 1: Formular rendern lassen

Das Skript lädt die Formular-JSON und baut daraus Felder, Labels und Optionen in der gewünschten Sprache – mit HTML-Validierung (required, maxlength, type="email", min/max).

<div class="mf-slot" data-machma-form="beispielhotel/kontakt" data-locale="de"></div>
<noscript>Bitte JavaScript aktivieren oder anrufen: +43 …</noscript>
<script src="https://forms.machma.app/v1/embed.js?v=1" defer></script>

<style>
  .mf-slot { min-height: 640px; }   /* Höhe an das Formular anpassen */
</style>

Modus 2: eigenes HTML übernehmen

Volle Kontrolle über Markup und Design: das Skript übernimmt ein vorhandenes <form>. Die name-Attribute müssen denen der Formular-JSON entsprechen. Einzelne Checkboxen ohne value-Attribut werden als Ja/Nein gesendet, Gruppen mit gleichem Namen als Liste.

<form data-machma-form="beispielhotel/kontakt" data-redirect-url="/danke-zimmer">
  <label>Name <input name="name" required maxlength="100"></label>
  <label>E-Mail <input name="email" type="email" required></label>
  <label>Nachricht <textarea name="nachricht" required maxlength="5000"></textarea></label>
  <label><input type="checkbox" name="datenschutz" required> Ich akzeptiere die Datenschutzerklärung</label>
  <button type="submit">Absenden</button>
</form>
<script src="https://forms.machma.app/v1/embed.js?v=1" defer></script>

data-Attribute

AttributBedeutung
data-machma-formsite/form – Pflicht
data-localeSprache (de, en). Standard: lang des <html>-Elements
data-redirect-urlüberschreibt das Redirect-Ziel für diese Einbindung – nur relative Pfade oder eigene Domains (Regeln)
data-success-messageeigene Erfolgsmeldung, wenn es keinen Redirect gibt
data-no-redirectnie weiterleiten, immer die Erfolgsmeldung zeigen
data-endpointandere Service-URL (z. B. lokal http://localhost:8080)

Am <script>-Tag schaltet data-styles="off" die eingebauten Standard-Styles ab.

Kein Layout-Sprung

Der Platzhalter bekommt eine min-height in der ungefähren Höhe des fertigen Formulars. Sonst rutscht der Inhalt darunter beim Laden nach unten, und die Core Web Vitals (CLS) leiden.

Astro

Im Moment genauso wie jede andere Seite. Überschrift, Text und Kontaktdaten bleiben normales statisches HTML; nur das Formular entsteht per JS. Für SEO ist das unkritisch – Formularfelder ranken nicht. Mit View Transitions initialisiert sich das Skript bei astro:page-load von selbst.

<!-- src/components/KontaktFormular.astro -->
<div class="mf-slot" data-machma-form="beispielhotel/kontakt" data-locale="de"></div>
<noscript>Bitte JavaScript aktivieren oder anrufen: +43 …</noscript>
<script is:inline src="https://forms.machma.app/v1/embed.js?v=1" defer></script>

<style>
  .mf-slot { min-height: 640px; }   /* Höhe an das Formular anpassen */
</style>

Ein Astro-Wrapper als npm-Paket (@machma/forms-astro), der das HTML schon beim Build rendert, ist geplant.

Content-Security-Policy

Hat die Seite eine CSP, muss sie https://forms.machma.app unter script-src und connect-src erlauben:

Content-Security-Policy: script-src 'self' https://forms.machma.app; connect-src 'self' https://forms.machma.app

Die Standard-Styles werden als <style>-Element eingefügt. Erlaubt deine CSP das nicht (style-src ohne 'unsafe-inline'), setze data-styles="off" und style die Klassen selbst – das Formular funktioniert in jedem Fall.

Styling

Kein Shadow DOM: alles lässt sich mit normalem CSS gestalten. Die wichtigsten Klassen und Custom Properties:

:root {
  --mf-accent: #1f5f4a;      /* Button, Fokus */
  --mf-accent-ink: #fff;
  --mf-error: #b3261e;
  --mf-border: #c9c8c2;
  --mf-radius: 6px;
  --mf-gap: 1rem;
}
.mf-form     { }  /* das Formular */
.mf-field    { }  /* ein Feld: Label, Eingabe, Hilfe, Fehler (+ .mf-field--email usw.) */
.mf-label    { }
.mf-input    { }  /* input, select, textarea */
.mf-option   { }  /* Radio/Checkbox mit Text */
.mf-help     { }
.mf-error    { }  /* Fehlermeldung pro Feld */
.mf-invalid  { }  /* ungültige Eingabe */
.mf-submit   { }
.mf-status   { }  /* „Wird gesendet …“, Fehler (+ .mf-status--error) */
.mf-altcha   { }  /* Hinweis zum Spamschutz */
.mf-success  { }  /* Erfolgsmeldung */

Der Container bekommt die Zustandsklassen mf-loading, mf-ready, mf-sending und mf-sent. Zusätzlich feuert er die Events machma:success und machma:error mit der Server-Antwort in event.detail.

Was das Skript sonst tut

  • Ergänzt ein unsichtbares Honeypot-Feld, die Sprache und den ALTCHA-Spamschutz.
  • Holt die Spamschutz-Aufgabe erst, wenn jemand ins Formular klickt, und rechnet sie im Hintergrund (unter einer Sekunde).
  • Sendet per fetch als JSON, zeigt Fehler pro Feld und eine Erfolgsmeldung – oder leitet zur Danke-Seite weiter.
  • Kein Framework, keine Cookies, keine Drittanbieter. Texte nur per textContent, nie innerHTML.
  • Versioniert über ?v=1: neue Versionen brechen keine bestehenden Einbindungen.

Ohne JavaScript

Der Spamschutz braucht JavaScript, deshalb wird ohne JS nie versendet. Zeige per <noscript> eine Telefonnummer oder Mailadresse an.
